# Development roadmap

As of September 30, 2026. These are proposed stages, not completed work or promised delivery dates. Versions after the current alpha are provisional.

| Stage | Work | Gate before describing it as complete |
| --- | --- | --- |
| 0.1.0-alpha | Initial Domain 1 workbook and guides, synthetic examples, citation, transparent status, working paper | Verify files and links, retain calculation-check record, publish a formal prerelease if authorized and technically available |
| 0.2 development | Improve Domain 1 and develop resources for remaining domains in manageable increments | Each new resource has instructions, sources, limitations, attribution, and documented maintainer checks |
| 0.3 review | Obtain independent review of defined resource versions | Actual review records, conflicts disclosed, issues resolved or clearly documented, public excerpts shared only with permission |
| 0.5 pilot | Plan and conduct a small feasibility evaluation with participating organizations | Protocol, permissions, appropriate ethics review determination, defined measures, baseline information, documented use and analysis |
| 1.0 candidate | Consider a stable resource package with maintained regulatory mapping | Documented review coverage, reproducible examples, material issues resolved, maintenance ownership and change process, evidence-supported scope |

## Immediate priorities

1. Verify formula and display behavior in supported native spreadsheet applications and record application/version details.
2. Seek practitioner review of Domain 1 using the [review brief](docs/practitioner-review/README.md).
3. Prioritize Domain 2 policies, Domain 5 subrecipient monitoring, and Domain 6 internal controls with practitioner input. Other domain folders retain their original scope.
4. Expand source mapping, document applicability decisions, and establish periodic source checks.
5. Refine the proposed evaluation in the [working paper](FGCF_journal_article.md) before recruiting sites or claiming results.

## Evidence and maintenance

Track material changes in [CHANGELOG.md](CHANGELOG.md). Update [STATUS.md](STATUS.md) with dated evidence. Preserve earlier versions in Git history. Use semantic version labels for reviewable resource packages, not as a claim of effectiveness.

The project lead currently maintains the repository. An advisory council, additional maintainers, partnerships, funding commitments, and pilot participants have not been documented. Any future governance arrangement should identify real participants and their responsibilities after they agree.
